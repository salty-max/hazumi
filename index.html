Matter

A typed 2D graphics library for sketches, generative work and games. The drawing API does not rasterise — it encodes a command stream that WebGL2, Canvas2D, SVG and a headless recorder each consume on their own terms.

A sketch

import { sketch } from 'matter';
import { webgl2 } from 'matter/backends/webgl2';

sketch({ backend: webgl2(), width: 600, height: 600 }, () => {
  return ({ background, circle, fill, width, height, t }) => {
    background('oklch(0.15 0.02 260)');
    fill('oklch(0.72 0.18 250)');
    circle(width / 2, height / 2, 200 + Math.sin(t) * 80);
  };
});

The context is destructured in the draw callback rather than injected onto window. That keeps the terseness of a global-style sketch — bare circle, fill, width — while staying fully typed, and because the same object is mutated in place, reading t or width costs nothing per frame.

Why it exists

Drawing APIs usually rasterise as you call them, which welds what you drew to how it was drawn: the output cannot be exported as vectors, re-rendered at another resolution, or tested without a browser and a pixel diff. Renderers built for GPU throughput avoid that by handing you buffers and pipelines instead — at which point a circle stops being one line of code. Matter keeps the short API and puts a typed command buffer behind it.

100k shapes10.0 ms per frame, one draw call — 60% of the 60fps budget
AllocationZero in steady state: 0.0 kB heap delta over 200 frames
BackendsWebGL2, Canvas2D, SVG and a headless recorder, from one command stream
Agreement18 scenes verified pixel-by-pixel across backends
ColourOKLCH throughout, so blends stay perceptually even
RandomnessSeeded by default — a sketch renders identically every run

Not there yet

Pixel access, a fixed-timestep game loop, and a WebGPU backend. Text renders from a runtime SDF rather than MSDF, so corners soften well above the atlas resolution. Not published to npm.
